# 内部工具包的 stella3 skill 同步到原稿最新版(小 spec)

## 1. 目标覆盖声明

覆盖目标清单 2026-10-03「stella 窗口转来的同步请求」一行里的插件副本部分。不覆盖:本机全局规则直通流程第 3 步补半句(规则文件,等 Tony 在本会话点头),以及随它镜像的内部工具包 WORKFLOW.md 与核心 skill 的对应句。公开 kit 不涉及(stella3 是内部专属)。

## 2. Prior art

原稿在 stella3 仓 `skills/stella3/`,内部工具包是同步副本;沿用「原稿改了、副本跟」的既有做法。

## 3. 现状与做法

查证(git,只读):副本上次同步点是原稿提交 bcb358fb(2026-09-29,对应插件 1.7.1)。之后原稿有四批改动没同步过来:运维信息动作(`ops` 工具)、取消下一检查点参数、取消阶段改按进度、「要别人做的事:建成对方的待办,先复述确认」;语言规定一条两边已经一致。副本里还写着线上工具已取消的阶段与下一检查点。

做法:以 bcb358fb 为基准、原稿主干 afcf5eea 为新版,对副本做三方合并(`git merge-file`),六个文件(SKILL.md、子代理定义、README、三个例子)全部无冲突;新增两个例子(hand-to-other、ops)。合并后副本与原稿只差本仓自己的一处差异:派子代理写 `dev-toolkit:stella-recorder`(新一节里的一处同样补上前缀)。内部工具包 README 的 skill 表、子代理表与版本说明跟着改,版本升到 1.9.0。

工具侧有三处改动原稿已写、线上还没发布(待办视图取消「我在等谁 / 谁在等我」;别人交来的条目带「交给我的人 / 交给我的时间」;新建成功返回「负责人」)。stella 窗口说明按新写法同步不会出错:没有「负责人」字段时规则就是不点名。

## 4. 验收

- AC1 副本的 SKILL.md、README、五个例子与原稿 afcf5eea 逐字相同,只允许 SKILL.md 里 `subagent_type` 带 `dev-toolkit:` 前缀这一种差异;子代理定义与原稿逐字相同。
- AC2 副本里所有 `subagent_type` 都带前缀;子代理定义的 `tools` 含 `mcp__stella__ops`;语言规定那一条仍在。
- AC3 副本里不再把线上已取消的动作(改阶段、下一检查点、执行人)当可用动作写。
- AC4 内部工具包 README 的 skill 表、子代理表、版本说明与新内容一致;`claude plugin validate` 结果不比改前差。
- AC5 合并并更新本机插件后,真机做一次只读查询(我的待办),子代理定义能加载、回执是中文。

## 5. 回滚

`git revert` 合并提交;本机 `claude plugin update` 回到上一版即可(插件缓存里留着 1.8.1)。

## 6. 追加:第二次同步(原稿 0c7262d8,撤回完成 / 删除待办)

出处:stella 窗口再次转来同步请求;原稿这批对应 Tony 2026-10-03 在该窗口提的需求「stella 在对话里的 mcp 现在不能撤回完成、删掉新建的待办,这个权限给 mcp 加上」,工具侧已上线。
