# 同步两条规则到公开 kit、合作方工具包与维护者本机规则(spec)

日期:2026-10-16。出处:Tony 在本会话的原话「这个没事，你可以全部同步一下」——接在内部工具包加完两条规则的汇报之后:「会留下无头进程的操作,先定好定时清理」与「要用户在命令行输入的内容,先放进剪贴板」;汇报里写了公开 kit、合作方的两个工具包、维护者本机的全局规则都还没有这两条。按「全部」理解为两条都同步、几处都同步。

## 1. 目标覆盖声明

覆盖目标清单 2026-10-16「这个没事，你可以全部同步一下」一行。同步面:本仓公开 kit 的中文、英文、Codex 三套;合作方的两个工具包(Claude 版、Codex 版,不在本仓,在各自仓库改);维护者本机的全局规则(不在任何仓库);内部工具包里注明「上游已同步」的对照说明。不覆盖:内部工具包的机器卫生巡检(孤儿检测只认测试进程,另议)。

## 2. 标准原文

两条规则的原稿在内部工具包,公开版就是本仓 README 改完后的文字:中文七之四第 3 条与新增的七之五,英文 7d 第 3 条与新增的 7e。要素:

- **定时清理**:凡是做完这一步还留在后台、没人盯着的进程(代码在运行时起的无界面浏览器、子进程、常驻 worker、定时作业,部署时起的后台容器或守护进程,会话自己在本机或服务器上用 `nohup`、`&`、`docker run -d`、`tmux` / `screen` 留下的进程、agent-browser 会话、批量会话进程),动手前先定好定时清理:① 谁来扫——不依赖启动方、按时间扫(服务内定时器按登记表扫、启动时先清自己上次留下的,或宿主机 cron / systemd timer / launchd);会话里起的把 `timeout -k` 加在真正长跑的命令上(macOS 用 `gtimeout`,`tmux` 里起完核对进程真的在跑),后台容器打标签由宿主机按标签和创建时间清;容器的 `init`、内存与进程数上限、重启策略只防资源耗尽,代替不了定时扫;② 按什么认——只认同一个服务、部署或会话登记过的进程,结束前核对启动时间与命令行,对不上只删登记;③ 清到什么程度——最长存活时间、同时存活数量上限,先正常关再强制结束整个进程组,记日志。测试时当场关掉的进程归第 1 条;配不了的写明原因与人工检查办法。七.4「进程约束」与评审句配套加半句。
- **剪贴板**:要用户自己输入的内容(终端命令、`!` 前缀命令、`/goal` 等斜杠命令、登录命令),主对话在给出前(复述句之后)先放进剪贴板,回复照样给代码块并写「已放进剪贴板」。五条:① 怎么放、怎么读回——先写私有临时文件(单引号或带引号的 heredoc,不许 `echo "…"`,不留行尾换行),从文件放、按字节 `cmp` 读回,三平台命令;② 放的就是原文(多条合并,贴到不同地方只放最先用的并写明);③ 不放密钥真值、授权码令牌本身不放,不覆盖用户正要粘贴的值(用户说值在剪贴板里先存进私有临时文件;流程本来就要从剪贴板粘贴值时这一轮不放并说明);④ 只有主对话放,子代理不动;⑤ 放不进去写「剪贴板不可用:<原因>」,会话跑在远程机器上同样。七.4 开工摘要的 `/goal` 括注指向这一节。

## 3. 各面改写规则

- **公开 kit 通用**:不出现内部名称(内部项目名、内部工具名、内部令牌变量名、内部主机与仓库路径);依据照 kit 现有口径写「一个真实项目的抓取服务里……」;「按日志契约」指六之四(英文 6d)。kit 没有 references 文件,完整文字放 README,模板放压缩版。编号:进程清理是七之四(英文 7d),剪贴板是新增七之五(英文 7e),放在七之四之后、§八之前。
- **中文**(`README.zh-CN.md` + `plugins/workflow`):README 七之四引言与第 3 条、七.4 两处半句与 `/goal` 括注、新增七之五;模板 §3 第 10 条、§7 派工句与评审句、剪贴板一条;`docs/DEPLOYMENT.md.tmpl` 上线后核对一条;`agents/mechanical.md` 一句;0.20.0 → 0.21.0。
- **英文**(`README.md` + `plugins/workflow-en`):同中文各处,忠实翻译;0.20.0 → 0.21.0。
- **Codex 版**(`plugins/workflow-codex`):模板 §3 第 10 条、派写入子任务的边界句与评审句、剪贴板一条、`DEPLOYMENT.md.tmpl` 一条;`parallel-do` 边界句与验收句;措辞用「子任务」;剪贴板只管终端命令与登录命令,不写 `!` 与 `/goal`;批量会话进程写 `codex exec`;0.17.0 → 0.18.0;README「Codex 版与 Claude 版的口径差异」一节记下这两处收窄。
- **合作方的两个工具包**:不在本仓,改法同 Codex / Claude 两套模板,各升一个小版本,README 版本说明各加一行;不写本组织的内部名称;它们的模板没有日志契约,清理日志写「每次清理记一行日志」。
- **维护者本机的全局规则**:不在任何仓库,改前备份;第一人称;与原稿同义。

## 4. 容易漏的输入与失败情形

1. 公开面或本仓 `docs/` 带进内部名称——评审逐个文件检索。
2. kit 编号没换(七之四第 3 条、七之五,英文 7d / 7e)。
3. 英文版漏要素(核对身份、时限位置、按字节比对、不覆盖用户正要粘贴的值)。
4. Codex 版照抄 `!`、`/goal`、Workflow、`mechanical` 或 `claude -p`。
5. 合作方工具包忘了升版(其中一个仓的 CI 会拦)。

## 5. 验收

- AC1 每一面都有第 2 节两条规则的全部要素;模板与派工句是压缩版,要素不缺。
- AC2 本仓的 README、`plugins/`、`docs/` 新增内容里没有内部名称;编号引用按第 3 节。
- AC3 英文与中文逐段对得上;Codex 两面没有照抄不存在的能力。
- AC4 各插件版本按第 3 节升;`claude plugin validate --strict` 对本仓的 Claude 插件通过(按 README「维护者:发版前检查」第 1 步)。
- AC5 维护者本机全局规则与原稿同义、有备份,与其它节不矛盾。

## 6. 回滚

各仓 `git revert -m 1` 合并提交后,再把插件版本升一个补丁号(不让版本号倒退,已装新版的使用者才能更新到回滚后的内容);全局规则用备份覆盖回去。纯规则文字,不涉及数据。

## 7. 评审

不属于高风险单元。实现:中文一个单元、英文加 Codex 一个单元(顺序做,同一分支)、合作方两个工具包各一个单元,都是 `sonnet` + `medium`(开跑时机器占用高,串行);全局规则由主对话改。评审:盲审 2 个(`opus` + `medium`)→ 裁决(`opus` + `high`),分流按档位表规则 2。
